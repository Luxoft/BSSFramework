# Legacy code

Part of the old API remains in the repository. Existing applications need it, but **it should not be used in new code**. This list makes it easy to recognise.

> No removal plans are recorded anywhere in the repository. If they appear, state them in this document and in `[Obsolete]` messages.

## How to recognise it

- Projects and folders with `Legacy` in the name.
- Extension methods `AddLegacy…` and `AddSupportLegacyServices` in the DI composition. In `SampleSystemGeneralDependencyInjectionExtensions` they are grouped under the `// Legacy` comment.
- Projections `*.LegacyProjections`.

## Projects

| Project | Contents |
|---|---|
| `Database/Framework.Database.Legacy.Abstractions` | `IDAL`, `IAuditDAL`: the old data access interface |
| `Database/Framework.Database.Legacy.Domain` | Audit revision models (`DomainObjectRevision`, `DomainObjectPropertyRevisions`, `ObjectModificationInfo`, …) |
| `Database/Framework.Database.NHibernate.Legacy` | `NHibDal`, `NHibObjectStatesService`, `AddLegacyNHibernateSettings` |
| `Database/Framework.Database.EntityFramework.Legacy` | `EfDal`, `EfObjectStatesService`, `AddLegacyEntityFrameworkSettings` |
| `Infrastructure/Framework.Infrastructure.Legacy` | Base controllers `ApiControllerBase<…>` and `ContextEvaluator` |
| `Infrastructure/Framework.Infrastructure.Legacy.Default` | Default implementations: `SubscriptionDALListener`, `FixDomainObjectEventRevisionNumberDALListener`, target-system setup (`ITargetSystemSetup`), `EventDTOMessageSenderBase` |
| `AutomationCore/Framework.AutomationCore.Legacy` | The old integration-test base (`IntegrationTestBase`, `ContextEvaluator` extensions) |
| `_SampleSystem/SampleSystem.Domain.LegacyProjections` | Generated "old" projections (generated by `LegacyProjectionGeneratorConfiguration` without `DependencySecurity`) |

## What counts as legacy in the DI composition

In `AddGeneralDependencyInjection`, under `// Legacy`:

| Call | Purpose |
|---|---|
| `AddSubscriptions`, `AddSubscriptionManagers` | Event subscriptions and subscription managers |
| `AddLegacyGenericServices`, `AddLegacyDefaultGenericServices` | Old generic services |
| `AddContextEvaluators` | `IContextEvaluator` |
| `AddLegacyNotification` | Wiring of notification sending |
| `AddConfigurationSystemConstants`, `AddConfigurationTargetSystems` | System constants and target systems of the Configuration subsystem |
| `AddBLLSystem` | BLL context registration |
| `AddSupportLegacyServices` | DTO mapping (`SetDTOMapping`) |

Some of these calls remain relevant (for example, subscriptions: see [notification.md](subsystems/notification.md)). "Legacy" there means the mechanism lives in the old infrastructure, not that it is unnecessary.

## Rules for developers

1. Do not add references to `*.Legacy*` to new projects if you can avoid it.
2. When editing legacy projects, make minimal changes and preserve compatibility.
3. Write new integration tests on `SampleSystem.IntegrationTests` + `Framework.AutomationCore`, not on `Framework.AutomationCore.Legacy`.
4. If you find a replacement for a specific legacy type, mark it `[Obsolete("Use … instead")]` and describe the replacement in this table.
